# 广州陈家祠 RAG 知识库

本目录为“广州陈家祠文旅 RAG Agent”准备可追溯、可更新的本地知识。资料按用途分层：事实语料、原始数据、来源登记和评估题彼此隔离，避免过期公告或示例答案影响真实回答。

## 目录结构

```text
chen_clan_academy/
├─ README.md
├─ knowledge/                         # 默认可向量化的事实语料
│  ├─ 01_basic_info.md                # 开放、交通、票务入口、联系信息
│  ├─ 02_history_architecture.md      # 历史、文化、布局、保护科技
│  ├─ 03_visit_services.md            # 游览路线与服务提示
│  ├─ 04_events_notices.md            # 有效/过期的动态公告
│  ├─ 06_ticketing_rules.md           # 购票、预约、入馆、订单规则快照
  │  ├─ 07_ornament_crafts.md           # 七类建筑装饰工艺总览
  │  ├─ 08_ornament_items.md            # 105 条具体装饰名称、类型与简介
  │  └─ 09_ornament_locations.md        # 105 条装饰的题材类型与摆放位置索引
├─ sources/
│  └─ source_registry.md              # 来源、可靠等级、适用范围和时效
├─ raw/
│  └─ chenjiaci_ornaments_source.json # 装饰条目原始结构化数据，不直接检索
└─ evaluation/
   └─ faq_eval.md                     # FAQ、路由和拒答评测集，默认不直接检索
```

## RAG 摄取范围

- **默认摄取**：仅摄取 `knowledge/` 内 Markdown。
- **默认排除**：`raw/` 仅保留原始数据；`evaluation/` 用于测试，不应作为回答依据，以免旧答案、示例措辞或动态规则污染检索结果；`sources/` 用于追溯，不作为主要答案语料。
  - **切块建议**：以二级、三级标题为优先边界。`08_ornament_items.md` 与 `09_ornament_locations.md` 均必须按每个 `## 装饰名称` 切分为独立 Chunk；其他文档应避免跨越不同时间状态或不同工艺类别。
- **检索元数据**：构建向量库时为每个 Chunk 附加 `document`、`category`、`source_id`、`verified_at`、`valid_from`、`valid_to`、`status` 等字段。来源与时效字段可从 `sources/source_registry.md` 和文档内“来源与核验”章节建立映射。

## 时效与准确性规则

1. 开放时间、票务、预约、余票、临展和闭馆属于动态信息；优先检索 `04_events_notices.md`、`06_ticketing_rules.md`，并按当前日期过滤失效内容。
2. 已标记“已过期”的公告仅可用于历史问题或回归测试，不能回答为当前安排。
3. `06_ticketing_rules.md` 是 2026-07-23 的官方小程序规则快照。涉及具体订单、优惠资格、实时场次或余票时，必须引导游客到官方公众号/小程序或现场确认。
4. 来源有冲突时必须同时说明差异或采取不含冲突字段的安全表述。例如陈氏书院的落成年份存在 1893/1894 两种公开表述。
5. 没有资料或无法实时核验时，不编造答案；说明限制并提供馆方官网、官方公众号/小程序、现场服务台或咨询电话等核验路径。
6. 任何 RAG 或 Agent 模块不得收集、保存或要求用户提供身份证号、订单号、二维码、支付信息、导游证、团员信息或盖章材料。

## 回答与引用要求

- 历史、建筑和装饰问题：基于检索到的馆方/政府资料作答，可简洁标注资料来源。
- 动态问题：回答中注明“以官方最新公告为准”和资料核验日期。
- 单件装饰问题：同时返回装饰名称、工艺类型与简介；现场位置若未被可靠资料确认，不得虚构具体方位。
- 保护科技和施工案例：明确资料年份，不能据历史案例推断当前施工、裂缝或开放状态。

## 维护流程

1. 新资料先保存原始链接、发布日期、采集日期、适用/结束日期和来源等级。
2. 将事实内容写入对应 `knowledge/` 文档；动态公告必须标注“有效、已过期或待确认”。
3. 更新 `sources/source_registry.md`，保留来源和冲突说明。
4. 更新后使用 `evaluation/faq_eval.md` 测试：检索命中、工具选择、日期过滤、来源冲突处理和拒答能力。
5. 通过测试后再重建向量库。

## 当前质量评估

当前知识库适合用于 **Demo 阶段的高质量静态 RAG**：历史、建筑布局、装饰工艺及 96 条单体装饰资料覆盖充分，且大部分来源可追溯至馆方或政府页面。对“陈家祠是什么”“灰塑是什么”“梁山聚义有什么寓意”等问题，预期能获得较稳定、可解释的召回结果。

仍不应承诺实时准确性的领域包括：当天是否开放、余票、临展、停车、无障碍服务、优惠资格和订单退改。要提升上线效果，后续应接入馆方公告/票务的授权或公开更新源，建立按日期增量同步机制，并在检索后增加来源引用与时效校验。
