# 陈家祠导游 Agent 模块总结与后续方向

更新日期：2026-08-05  
适用分支：`experiment/agent-orchestration-v2`

## 1. 当前定位

当前系统已经不是单纯的景点问答机器人，而是一个具备路线、现场状态、
受控讲解、问答恢复、游览总结和审计能力的导游 Agent 原型。

综合评价：

- 毕业设计或研究原型完成度约为 8.5/10。
- 真实景区产品成熟度约为 6.5/10。
- 核心优势不是自由生成大量文本，而是明确知道何时可以回答、依据什么回答、
  哪些状态允许修改，以及证据不足时如何安全关闭。

P4-01～P4-03 已基本实现；P4-04 当前只有馆外 POI 人工填写模板，
`NearbyRecommendationService` 尚未正式接入 Graph，因此不能把整个 P4
阶段标记为全部完成。

## 2. 已形成的导游闭环

当前主流程为：

```text
开始导游
→ 选择经典/定制模式
→ 收集时长与偏好
→ 生成路线
→ 自动播放总体介绍
→ 前往点位
→ 到站并进行受控讲解
→ 游客提问或请求深入讲解
→ 完成、跳过或前往下一站
→ 必要时调整时间和重规划
→ 结束游览
→ 生成总结
→ 授予趣味称号和原创祝福
```

现有主要能力：

- 经典模式与定制模式的透明选择。
- 游览时长、兴趣、讲解风格和讲解语言偏好收集。
- 确定性路线生成和路线状态管理。
- 到站、完成、跳过、下一站、提前结束和重复结束处理。
- 剩余时间调整及受控重规划。
- 自动开场介绍和首站讲解衔接。
- 基于审核卡片和 Coverage 的点位讲解。
- 普通问答、追问及问答后恢复导览。
- 游客提问次数、完成点位、工艺和题材统计。
- 游览总结、趣味称号和原创祝福。
- Shadow 审计、状态写入保护和游客正文防泄漏。
- 944 项自动化测试基线。

## 3. 主要产品优势

### 3.1 有状态的完整导览

系统能够区分“计划去过”和“正式完成”，并维护待到达、讲解中、已完成、
跳过、提前结束等阶段。这使它具备真实导览流程，而不只是连续问答。

### 3.2 可审计和安全关闭

- LLM 不能直接修改 TourState。
- 导游事件必须经过受控解析和状态适配器。
- 讲解优先使用审核资料。
- Coverage、总结和称号均有可检查依据。
- 证据不足时不补造事实。
- 游客正文不展示来源 ID、路径、URL、原始 chunk 或内部工具名称。

### 3.3 定制信息能够进入后续流程

游客的时长、兴趣、风格和语言字段不只用于一次性问卷，还可以成为路线、
讲解策略、内容组织和游览后称号的输入。

## 4. 仍需丰富的内容

### 4.1 点位与对象级讲解卡

优先补充：

- 每个正式路线点位的完整讲解卡。
- 点位中可见对象、构件及其准确位置。
- 对象与灰塑、木雕、石雕、砖雕、陶塑等工艺的审核映射。
- 人物、纹样、吉祥寓意和相关故事。
- 首次讲解、重复讲解和深入讲解内容。
- 观察提示、常见追问和证据不足时的安全回复。

推荐内容关系：

```text
空间点位
→ 可见构件
→ 工艺
→ 具体对象
→ 题材或故事
→ 观察方法
→ 常见追问
```

### 4.2 更具记忆点的故事内容

需要增加与现场对象直接绑定的故事，包括人物典故、吉祥题材、工匠工艺、
晚清广州背景、宗族与科举历史，以及修缮前后变化。不能把泛化故事写成当前
点位的确定事实。

### 4.3 不同游客群体的版本

建议继续建设儿童、亲子、研学、摄影观察、建筑专业、工艺爱好者、老年简洁、
静听、时间紧张和无障碍友好版本。

### 4.4 多语言资产

目前系统能收集 `language`，但不等于已实现多语言讲解。后续需要建设：

- 多语言审核术语表。
- 点位、工艺、人物和典故的规范译法。
- 多语言讲解卡、安全提示、称号和祝福。
- 未审核语言的透明回退规则。

文博内容不应只依赖中文正文的即时机器翻译。

### 4.5 馆外附近推荐

P4-04 应优先准备附近饮食、历史文化场所、公园休息空间、工艺文创、交通和
游客服务等少量审核 POI 卡。营业、价格、排队和交通耗时必须作为易变信息，
携带来源、核验时间或明确的不保证说明。

## 5. 可增加的游客创意卖点

### 5.1 岭南工艺侦探

在点位讲解中提供可选观察任务，让游客主动寻找屋脊人物、纹样、工艺差异或
构件细节。游客回答后再揭晓审核答案，但不强迫互动或触摸文物。

### 5.2 七艺图鉴

游客实际听到或发现一种工艺后解锁对应图鉴。未讲解、跳过或证据不足的内容
不得解锁，也不得写入 Coverage。

### 5.3 错过内容的短版补听

游客跳过点位或提前结束时，可以选择听取该点最具代表性的 30 秒审核内容，
或者保留到下次游览。补听内容和正式完成状态必须分开记录。

### 5.4 多人共游模式

分别收集儿童、家长、老人或同行者的显式需求，在同一条少走路路线中提供
“共同概览 + 分层内容 + 可选观察任务”。不得根据年龄或身份自动推断偏好。

### 5.5 游览记忆卡

结束时生成可分享的文字或视觉卡片，展示实际完成点位、解锁工艺、听过的故事、
提问次数和趣味称号。所有内容只能来自审计状态。

### 5.6 快速收尾路线

游客表示只剩十分钟、疲劳或希望少走路时，基于当前正式位置生成安全的剩余
路线，并明确哪些内容因时间不足未覆盖。

### 5.7 方言与语音体验

未来语音能力可重点支持普通话、粤语、英语、韩语、慢速讲解、儿童语速和
静听模式。粤语讲解可以成为岭南文化场景的明显差异化卖点。

推荐将“岭南工艺侦探 + 七艺图鉴 + 游览记忆卡”设计为一套连续体验，作为
游客最容易感知的核心卖点。

## 6. 技术优化方向

### 6.1 从全局关键词竞争转向状态约束识别

现有语义路由仍较依赖关键词、正则和优先级，已出现定制表达、跳过、到站和
结束语义之间的错误竞争。中期应采用两阶段路由：

```text
根据当前状态计算本轮允许的操作集合
→ 只在允许集合中识别游客意图
→ 使用确定性验证器执行
```

例如正在收集语言时，应只开放设置语言、跳过语言、取消定制及必要安全请求，
不应让所有导游事件与画像操作同时竞争。

### 6.2 拆分 Graph 模块

`agent_graph.py` 已超过三千行。建议逐步拆为：

```text
graph/
  routing.py
  nodes/profile.py
  nodes/tour_lifecycle.py
  nodes/narration.py
  nodes/qa.py
  nodes/post_visit.py
  nodes/nearby.py
  edges/tour_edges.py
  edges/post_visit_edges.py
```

根 Graph 文件只负责注册节点和连接关系。

### 6.3 统一游客偏好与渲染风格

当前 `VisitorProfile.explanation_style` 与 `NarrationStylePolicy.style_id`
属于两套不同枚举。需要增加版本化映射层：

```text
游客风格偏好
+ audience_mode
+ interaction_mode
+ knowledge_level
→ GuidancePolicy
→ NarrationStylePolicy
```

避免游客选择故事风格后，实际审计仍显示 `neutral`。

### 6.4 建立统一内容验证器

为点位卡、故事卡、风格卡、称号卡、POI 卡和多语言卡建立统一验证命令，自动
检查 ID、引用、来源、审核状态、过期易变信息、非法占位符、缺失翻译和内部
字段泄漏风险。

### 6.5 增加属性测试和对抗表达

在现有示例测试外，增加标点、简繁体、中英文数字、中英文混输、主语省略、
口语缩写、否定、多意图、重复输入、状态过期和 Thread 恢复测试。核心不变量：

- 控制意图不得落入自由 LLM/RAG。
- 问答不得误写 TourState。
- 画像表达不得推进路线。
- 结束态请求不得重启路线。
- 重复请求不得重复写入 Coverage 或完成点位。

### 6.6 完善 LangSmith 验收资产

建立固定的画像路由、导游生命周期、游览后服务、多语言对抗和状态不变数据集。
每次提交记录 tested commit、Thread ID、Trace URL、节点路径、状态差异和游客
正文；缺少元数据时必须标记为 `metadata_unavailable`，不得补造。

### 6.7 配置与密钥安全

- `.env.example` 只能保留占位符。
- 实际密钥放入被忽略的 `.env`。
- 轮换任何曾写入示例文件或截图的密钥。
- CI 增加 secret scanning。
- 启动时检测缺失配置，但不得打印密钥。

## 7. 推荐实施顺序

1. 完成 P4-04 并接入馆外推荐的受控结束后服务。
2. 扩充核心路线的对象级讲解卡与故事卡。
3. 统一游客风格偏好和实际渲染风格。
4. 实现“工艺侦探 + 七艺图鉴 + 游览记忆卡”。
5. 建立统一内容 Schema 验证工具。
6. 建设中英文审核内容，再扩展粤语和其他语言。
7. 最后接入 TTS、语速控制和多语言语音。

## 8. 总结

该 Agent 的底层控制能力、安全边界和可审计性已经超过普通导游 Demo。
下一阶段不宜只继续增加节点，而应把重点放在高质量现场内容、状态约束语义路由、
风格映射统一和游客可直接感知的创意体验上。完成 P4-04、内容扩充与核心卖点后，
系统将更接近一个能够在真实文博场景中试用的数字导游产品。
