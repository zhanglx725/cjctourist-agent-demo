## 从快照确认的问题

1. **同一风格的句式复读明显。** 闺蜜唠嗑三条都以“这个细节挺有意思”或“咱们接着往前逛”收束；兄弟搭子反复“咱们抓重点”；探秘闯关反复“找到它了”。这不是可感知的连续人格，而是可预测的口头禅。
2. **模型在连接语中擅自承担了事实表达。** 例如将审核句“该构件采用灰塑工艺”扩成“这个构件用的是灰塑工艺”；把空间/对象名提前写进开场。现有校验拦截年代、传说、排名等高风险词，但未能识别这种近义复述和未明确授权的可见性断言。
3. **样本知识包过薄。** 每条只有一条抽象审核句（如“该构件采用灰塑工艺”），不足以支持“先找位置、再辨造型、再理解工艺”的生动讲解。模型只能重复该句或用通用氛围词填充。
4. **服务区已从正文分离，但快照文件保存的是完整公共消息。** Streamlit 运行时会基于已验证 `stop_service_text` 独立显示“下一步提示”卡片；评审时应以游客端 UI 或公共消息的 `service_text` 字段检查视觉效果，不能把快照尾部的服务文字误判为正文。

## 下一轮改造（先不换 API）

1. 把快照知识包升级为每点至少三个已审核、可观察的事实组：位置/空间、工艺或材料、对象形态或题材；月台作为固定真实样本。
2. 将 LLM 输入改为“事实 token + 受控观察意图”，而不是把完整事实句直接交给模型后仅靠提示禁止其复述；服务端负责还原对象名、位置与审核句。**本轮已完成第一步：`RoleDiscoursePlan` 不再向模型序列化事实原文或 ID，仅传递段落序号与空间/工艺/对象主题。**
3. 为四种对照风格建立反复读约束：保存最近表达；同一风格在同批三条样本中不得重复开场或收束的标准化句子；命中后仅允许一次重试。
4. 语料库继续扩写，但每条须是无实体事实的观察动作、转场或收束，并按场景/对象类型选择；不得把“抓重点”“接着看”“找到线索”作为默认兜底。
5. 新增体验门槛：同一风格三条快照中开场、桥接、收束均不重复；连接语不得含审核事实中的专名/对象名，除非该位置由服务端 token 还原；四种风格盲读可区分。

## API 决策

当前 API 的质量基线不足，但失败首先暴露的是知识包粒度、连接语协议和重复控制，而不是单独证明模型能力不足。

完成上述改造后，使用同一批真实月台事实、同一四种风格和相同随机性设置，分别保存当前 API 与候选 API 的快照。仅当候选 API 在风格可辨识、复读率、事实边界合格率、延迟和成本上同时更优时，再迁移角色成文 API。

事实不再传给模型后，模型将未经授权的具体名称、位置和形态补进连接语的问题显著减少；这验证了事实槽位边界有效。仍存在的主问题是风格“关键词合规”被误当成风格本身：闺蜜、搭子、探索三种风格分别反复出现“挺有意思”“抓重点”“线索/找到”等句式。

### 已进入第三轮的改造

1. 将三个角色的 `required_markers` 从固定口头禅改为更宽的动作型风格信号，避免模型为过门而重复同一句。
2. 将审核过的固定语料以 `expression_palette` 注入自然成文提示：仅供借鉴观察动作、节奏与收束，不允许逐句照抄。
3. 保持事实不进模型、服务端原样插入、状态和安全校验不放宽。

### 第三轮验收标准

- 同一角色的三条样本开场、桥接、收束不得使用同一完整短语；
- 不得回到“有意思 / 抓重点 / 找到线索”作为默认填充句；
- 每条至少包含一种可感知但不新增事实的观察动作（收近视线、对照、连起关系或回到整体）；
- 仍维持 Active 12/12、fallback 0/12，且所有既有单元测试通过。

快照：[role_narration_20260817T195105_deepseek-expression-palette.json](../snapshots/role_narration_20260817T195105_deepseek-expression-palette.json)

技术指标仍为 12/12 Active、0 次旧版回退，且 64 项相关测试通过；但体验验收仍未通过。部分闺蜜、搭子和探索样本逐句复用了表达调色板，证明当前模型对“不可照抄”的纯提示约束不足。

同时确认原快照的 `fallback_count` 仅代表是否退回旧版讲解，不能代表自然模型是否成功。现已增加 `natural_component_fallback_used` 和 `generation_reason_code` 两个快照字段，以区分“模型自然成文发布”与“模型失败后由新固定语料发布”。固定语料兜底也已改为围绕审核事实分段，避免再次形成粘连长段。

## 第四轮：连续会话复读压力快照

`role_narration_20260817T195836_deepseek-audit-layout.json` 显示自然成文为 12/12，固定语料兜底为 0/12；但体验仍未通过：探索风三条的开场与收束完全相同，搭子风和古风也重复固定收束。这不是安全或布局问题，而是首轮样本之间没有共享真实 Thread 的最近表达记忆。

快照工具现改为按 `style_id` 将三类点位作为同一游客的连续三站执行，并在文件中记录 `continuity_mode: per_style_thread`。下一次快照将测量真实会话内的去复读门，而不是将每条样本误当成首次见面。若连续会话仍无法保持自然成文且出现大量固定语料兜底，再以相同快照对候选 API 做成本、延迟、风格区分度和复读率对照。

结论：当前 API 在事实边界、分段布局和故障恢复上已经可作为生产基线；但在连续会话中遵守“不复读、仍自然、且不新增事实”的综合指令时，5/12 需要固定语料兜底，未达到“丰富灵活”的体验目标。因此不直接全量切换，也不继续只靠扩写语料解决；正式进入候选 API 的盲测对照。

### 候选 API 对照条件

1. 保持完全相同的事实槽位、风格卡、温度、连续会话快照和安全门。
2. 仅替换角色成文模型的提供方/模型名，并用新的 `--provider-label` 保存快照。
3. 候选 API 至少应达到：12/12 Active、0 旧版 fallback、0 契约失败、自然成文转固定语料不高于 1/12；同时人工盲评四种风格可区分、无明显口头禅复读。
4. 若候选未达标，保留当前 API，并把自然成文改为“可控试验能力”，默认继续使用经过扩写的固定语料；若达标，再进行小流量灰度切换。

### 豆包首轮接入状态（2026-08-17）

快照 `role_narration_20260817T201913_doubao-ark.json` 的 12 条均为 `natural_discourse_fallback:model_unavailable:AuthenticationError`。这表示方舟认证未成功，最终游客文本全部来自固定语料兜底，**不能作为豆包质量对照结果**。已将快照工具升级为输出 `model_unavailable_count`，该值非零时会以非零状态结束，防止认证失败被误判为模型效果。
