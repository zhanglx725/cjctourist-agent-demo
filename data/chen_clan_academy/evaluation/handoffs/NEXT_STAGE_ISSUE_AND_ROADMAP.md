## 1. 目标与判断原则

项目目标不是把陈家祠资料检索出来后逐句回答，而是在不虚构事实、不突破现场安全边界的前提下，根据游客**已明确的时间、游览模式、兴趣、当前审核点位和实际游览进度**，组织连续导览。

下一阶段不应以“再写 Prompt”或“改成 KAG”作为主线。当前已经具备混合 RAG、确定性路线、`TourState`、`VisitorProfile`、到达/确认事件和多类知识卡。真正缺口是：修复已验证的控制层问题、完成证据驱动讲解、明确产品模式，以及按审核条件调度卡片。

所有后续改动遵循以下边界：

- 路线、到达、跳过、完成、重规划继续只由确定性状态机修改；
- 陈家祠对象、位置、工艺、故事和保护规则必须由本地审核资料或可追溯来源支持；
- 大模型可以组织语言或回答非项目通用闲聊，不能自行决定“陈家祠事实不需要检索”；
- 无证据、空间映射冲突、运行资格缺失或现场条件未知时，必须失败关闭或说明资料不足；
- 每个“已修复”必须同时有自动化回归测试和 LangSmith 实际链路复测。

| 项目 | 内容 |
| --- | --- |
| 问题描述 | 首轮问题是“无人机航拍”没有先执行全域禁飞，而是进入打卡候选。2026-07-30 LangSmith 又发现两条真实失败：①“我带相机来拍商业宣传片，需要提前办什么手续？”没有被认作商业拍摄，反而返回机位和构图；②“我在庭院休息区吃点东西可以吗？”没有回答庭院休息区的允许例外，而是被误判为到达事件并要求确认点位。 |

### P1-18 “我在某处 + 问题”被误判为已经到达

| 项目 | 内容 |
| --- | --- |
| 问题描述 | 用户问“我在庭院休息区吃点东西可以吗？”，系统进入 `clarification`，回答“我知道您已到达，但无法确认点位名称”，没有处理真正的饮食规则问题。该缺陷不只影响饮食；“我在月台可以做什么/这里能否使用闪光灯”等以当前位置为背景的问题也可能被到达事件抢占。 |
| 根因 | 当前到达识别正则把“我在”与“我到了/我到达了”放在同一组到达表达中，只要句子出现“我在……”就产生 `arrive_at_stop` 命中；它没有区分“我在某处”这一静态位置背景与“我已经到达某处”这一状态变更操作。安全词没有先命中时，该错误会直接进入 A1 点位解析和到达澄清。 |
| 当前现状 | `implemented_pending_langsmith_verification`。到达解析已移除无条件“我在”命中，只保留“我到/我到了/我已经到达/我来到了”等明确状态变化和受唯一待到达点约束的裸“到了”同义词。点位问答增加“能看到什么/可以看到什么”表达，因此“我在月台能看到什么？”进入只读点位清单，不写 TourState；安全问句仍由安全门控优先处理。 |
| 期望状态 | “我在庭院休息区吃点东西可以吗？”首先作为饮食规则问题处理；“我在月台能看到什么？”作为点位问答处理；只有“我到了月台/我已经到达月台/到了”等明确状态变化表达才进入 `tour_event`。位置背景问句不得写入当前位置、到达状态或路线进度。 |
| 解决方案 | 在 A1 到达解析中移除无条件“我在”到达命中，或要求它同时具备明确抵达/刚到语义且不包含事实问句；先由现有安全、事实、点位问答等只读门控识别明确问题，再进入事件分类。不得依赖模型直接写 node_id；明确到达仍须经过审核节点解析和唯一待到达点门控。 |
| 验收 | “我在庭院休息区吃点东西可以吗？”不进入 `tour_event/clarification`；“我在月台能看到什么？”不记录到达；“我到了月台”“我已经到达月台”和路线中裸“到了”仍按现有契约工作；游览前后两种模式结果等价，TourState、当前位置和 VisitorProfile 保持不变。 |
| 自动化验证 | `test_tour_intent.py` 覆盖静态位置背景与明确到达对照；`test_agent_tour_state.py`、`test_agent_tour_qa.py` 证明“我在月台能看到什么？”进入只读问答；`test_agent_photo_qa.py` 证明庭院休息区饮食不被到达流程抢占。定向回归 91 项通过，完整回归 625 项通过；LangSmith 待复测。 |

## 10. P4：暂缓项目

以下能力具有价值，但不应在 P1/P2 未完成前开工：

- GPS、蓝牙信标和视觉识别自动定位；
- 基于长期行为的个性化推荐；
- 跨会话长期游客画像与数据库持久化；
- 实时客流、开放时间、展览或票务同步；
- 多语言完整导览与语音前端；
- 自动生成新知识卡或自动写入空间关联。

它们都要求额外的授权、现场数据、隐私设计或人工审核，不能通过当前聊天/RAG 逻辑安全替代。

```text
7. 冻结 P2-01 至 P2-03 的经典/定制模式契约
8. 实现受控卡片调度器，先接术语与比较，再接研究与摄影
9. 定义可信位置事件（地图点击/二维码优先）并做主动到点触发
10. 最后评估定位、多模态、长期画像和实时数据能力
```

## 12. 每个任务的统一完成标准

一个问题只有同时满足以下条件才可从问题池关闭：

1. 有清晰的唯一事实源和文件所有权；
2. 不改变 TourState、VisitorProfile、路线和空间数据的既定边界；
3. 有针对原始用户表达的自动化回归测试；
4. 有 LangSmith 新线程与连续线程实测记录；
5. 无效证据、无效节点、审核不足和现场未知条件均安全降级；
6. 更新问题池状态、证据链接和受影响测试；
7. 经负责人确认后才提交、合并或推送公共分支。
