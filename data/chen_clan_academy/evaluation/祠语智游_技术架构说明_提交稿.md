# 祠语智游——多角色沉浸式非遗智能导游

## 技术架构说明

**首届超级智能体大赛（2026 Super Agent）**  
**适用赛道：AI+旅游休闲**  
**当前阶段：陈家祠场景原型 Demo**

祠语智游面向文化场馆自助导览场景，以“确定性决策＋生成式表达”为核心架构。系统将游客画像、审核知识、空间关系、路线规则和游览状态作为可信底座；生成模型只在结构化内容计划和质量校验通过后，负责角色化语言表达。由此让路线、讲解、问答、进度与游后服务共享同一旅程状态，在提升沉浸感的同时保障文化事实、空间路径和业务状态可控。

![系统总体架构图](assets/03-system-architecture.svg)

### 架构组成与技术选型

| 层级 | 核心模块 | 当前作用 |
|---|---|---|
| 交互与应用层 | 文字交互入口、LangSmith Studio | 承载比赛 Demo 与运行观测；后续可接 H5、小程序、公众号或自助终端 |
| Agent 编排层 | Python、LangGraph | 编排语义归一、画像、路线、讲解、问答、进度与总结等状态化节点 |
| 确定性控制层 | VisitorProfile、TourState、QAContext、Coverage、Proposal | 管理画像、路线进度、连续追问、知识覆盖与受控变更 |
| 知识与空间层 | Markdown/JSON 知识卡、BM25、BGE、RRF、Chroma、NetworkX | 组织审核知识，完成混合检索、合法路径和步行时间计算 |
| 生成与质量层 | DeepSeek、ContentPlan、质量门、LangSmith | 生成角色候选，校验事实、路线、预算与安全边界，并记录审计结果 |

## Agent 工作流与状态管理

系统以 LangGraph 构建状态化 Agent 图，将“理解需求—选定路线—现场讲解—受控问答—进度更新—游后总结”拆分为可组合、可追踪的节点。语义归一与安全仲裁负责识别用户意图；画像节点收集语言、时间、兴趣、讲解深度与表达偏好；路线节点仅从审核模板与空间关系中选择可行方案；到站、讲解、问答和进度节点在统一状态上运行。

![Agent 工作流与状态管理图](assets/04-agent-state-workflow.svg)

| 状态对象 | 主要内容 | 技术价值 |
|---|---|---|
| VisitorProfile | 语言、时间、兴趣、讲解深度、角色偏好 | 为路线选择与表达策略提供稳定输入 |
| TourState | 当前点、已访问点、剩余点、路线状态 | 保证游览连续推进，避免讲解与现场脱节 |
| QAContext | 问题对象、证据范围、追问许可 | 支持“这里”“这个”“再讲详细一点”等连续追问 |
| Coverage | 已介绍工艺、对象、主题与提交记录 | 减少重复讲解，为游后总结提供真实依据 |
| Proposal | 路线变更候选与确认状态 | 防止自然语言未经确认直接改写路线 |

正式业务状态只由确定性节点原子写入；角色生成与校验节点不写入 VisitorProfile、TourState、路线或 Proposal。这一责任隔离使角色表达不会改变事实、路径和游客进度。

## 受控角色表达、质量门与当前实现范围

知识层通过场景过滤，将当前点位、问题类型和审核状态作为检索约束；BM25 负责对象名与术语等关键词召回，BGE 负责语义召回，RRF 融合排序，必要时进行条件重排。路线层基于审核路线模板、点位目录和空间拓扑，使用 NetworkX 计算合法路径与步行时间。模型不会自由生成路线、状态补丁、内部 ID、原始知识片段或工具执行指令。

![角色表达质量门图](assets/06-role-quality-gate.svg)

每次角色表达均以 ContentPlan 固定审核事实、内容结构、讲解预算、交互权限和安全边界。候选内容依次接受 Schema、事实 ID、路线一致性、公共输出安全、角色规则和预算校验；命中风格—场景白名单且全部通过时，才可有限 Active 展示。其余候选保持 Shadow 审计，或在超时、非法结构、事实漂移、预算超限和内部字段泄漏等情况下自动保留稳定正文。无论接管或回退，Coverage 均只提交一次并留存审计记录。

比赛版已完成确定性旅程主链；古风书生已在路线规划、路线开场和审核点位讲解中有限 Active；儿童友好与中性清晰已在白名单审核点位讲解中有限 Active。系统已完成角色候选生成、校验、Shadow 审计与故障回退机制，并通过完整回归 1118/1118、最新 Active 定向验证 59/59、18 种角色策略自动化验证及高风险角色人工抽样验证。角色化问答仍以 Shadow 方式运行，确保游客端始终获得稳定、审核边界内的答案。
