# 陈家祠比较卡库

本目录存放可被导游 Agent 调用的“比较卡”。比较卡的目的不是为景点排名，而是帮助导游在游客追问“陈家祠和谁不同、为什么值得看”时，给出有范围、有证据、能落回现场观察的回答。

## 使用规则

1. 每张卡必须明确比较对象、时间范围与建筑/机构类型；不得把跨时代、跨类型对象直接排成高低。
2. 陈家祠侧与比较对象侧均需有可核查来源。只有一侧有资料时，状态只能为 `evidence_collection`，不能输出差异性结论。
3. `visitor_conclusion_zh` 必须是面向游客的可观察结论，不可使用“全国第一”“最具代表性”等绝对化表述，除非来源明确支持并标注范围。
4. 导游生成时先读 `claim_strength`：`confirmed` 才可直接陈述；`cautious` 必须使用“可从……角度观察”“现有资料显示”等限定；`research_only` 仅供研究问答；`evidence_collection` 不得作为事实输出。
5. 比较卡只能增强讲解内容，不能改变路线、空间边、`node_id` 或文物—点位关联。

## 首批对比对象层级

| 层级 | 回答的问题 | 示例对象 |
| --- | --- | --- |
| 广州城市定位 | 陈家祠在广州历史景点中提供何种理解入口？ | 同为已核查的广州历史文化场所 |
| 同类建筑 | 它与岭南其他祠堂、书院有何异同？ | 合族祠、书院、宗祠 |
| 跨区域建筑 | 岭南祠堂与北方、江南祠堂可从哪些方面观察？ | 同时代、同类且资料充分的祠堂 |
| 工艺专题 | 某项工艺在陈家祠与其他地区传统中有何差别？ | 石湾陶塑、潮州嵌瓷、徽州砖雕等 |

详细维度见 `comparison_dimensions_v0.yaml`；首批卡的取证状态见 `comparison_card_catalog_v0.yaml`。

## 录入流程

1. 为比较对象登记权威来源、核验日期和可用范围。
2. 为每个比较维度分别填写双方证据，保留原始页码、链接或馆方资料定位。
3. 写出“相同点、差异点、现场观察提示、结论边界”。
4. 由人工审核对象是否同类、尺度是否可比、结论是否超出证据。
5. 审核通过后把卡的 `status` 改为 `approved`，并设置恰当的 `claim_strength`。
